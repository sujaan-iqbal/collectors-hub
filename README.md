# Collector's Hub

A responsive web app for collectors to browse a marketplace, discover community posts, and manage
a personal collection. Built as a React + TypeScript internship assignment submission.

**Live preview:** run locally with the steps below (see *Setup*).

---

## Setup instructions

Requires Node.js 18+.

```bash
npm install
npm run dev       # starts the dev server at http://localhost:5173
```

Other scripts:

```bash
npm run build      # type-checks and builds a production bundle to dist/
npm run preview    # serves the production build locally
npm run lint        # runs oxlint
```

No environment variables, backend, or authentication are required — all data is generated by a
mock async data layer (`src/data/api.ts`) that simulates real network latency and occasional
failures so the loading/error states are genuinely exercised.

## Project structure

```
src/
  components/   Reusable UI: cards, badges, search, filters, empty/error states, skeletons
  context/      React Context providers — Collections, Social (likes/saves), Toasts
  data/         Mock data generators, the simulated fetch layer, shared filter constants
  hooks/        useDebounce, useAsyncData
  pages/        Marketplace, ListingDetail, CommunityFeed, PostDetail, MyCollection, NotFound
  types/        Shared TypeScript types
```

## Routes

| Path                  | Page                                   |
|------------------------|-----------------------------------------|
| `/marketplace`         | Browse & filter listings                |
| `/marketplace/:id`     | Listing detail                          |
| `/community`           | Community feed                          |
| `/community/:id`       | Post detail                             |
| `/collection`          | My Collection (Owned / Wishlist / Selling tabs) |

## Libraries used

- **React 19 + TypeScript** — via Vite's `react-ts` template
- **React Router v7** — client-side routing, plus `useSearchParams` to keep search/filter/sort/tab
  state in the URL (so it survives navigation and the back button, and is shareable/bookmarkable)
- **Tailwind CSS v4** — utility styling, with a small custom design-token theme (`src/index.css`)
- No component library — all components (cards, badges, selects, toasts, skeletons) are hand-built
  to keep the bundle small and the design cohesive
- No external state library — collection and social state live in React Context, persisted to
  `localStorage`

## Assumptions made

- **No backend / no auth**, as permitted by the brief. All listings and posts are generated by a
  seeded mock data set (`src/data/mockData.ts`) so the data is stable across reloads, and refetches
  simulate a real request (latency + an ~8% chance of failure to trigger the error/retry UI).
- **"Add to Collection"** from the Marketplace adds an item to the **Owned** bucket; **"Add to
  Wishlist"** adds it to the **Wishlist** bucket. Both are duplicate-checked per bucket.
- **Estimated Value** in My Collection is seeded from the originating listing's price at the time
  it was added (a reasonable mock stand-in for a real valuation service).
- **Community "Save"** is tracked separately from the Marketplace wishlist, since saving a post and
  wanting to own the underlying item are different user intents.
- Filter/search/sort/tab state is stored in the URL query string rather than component state, which
  satisfies "maintain selected filters while navigating" for both in-app navigation and browser
  back/forward.
- Every 11th–13th mock image intentionally points at a broken URL so the missing-image fallback
  state is visibly exercised without relying on real network flakiness.

## Features implemented

**Functional requirements** (all three modules): browsing, search, category/condition filters,
price/newest sort, product & post detail views, add to collection/wishlist, like & save posts,
three default collection buckets with move-between-buckets and remove.

**Logical/edge-case handling:**
- Duplicate-add prevention per bucket, with a toast explaining why nothing changed
- Empty states (no listings, no search results, empty collection bucket) with contextual copy and
  a "clear filters" action where relevant
- Missing/broken image fallback (`SafeImage`) instead of a broken-image icon
- Loading skeletons matched to each layout (grid vs. feed vs. detail)
- Error state with retry, backed by a data layer that can genuinely fail
- Filters persist across navigation via URL search params
- Toast feedback on every mutating action (add, remove, move, duplicate blocked)

**Bonus features implemented:**
- Debounced search (300ms)
- Local persistence via `localStorage` for collections, likes, saves, and wishlist
- Skeleton loaders
- Responsive layout from mobile (bottom tab bar) through desktop (top nav)

## Design notes

The visual language is built around a *specimen / accession-catalog* motif — the way a museum or
archive labels and numbers a physical collection — since that's the real vocabulary collectors use
(condition grading, accession numbers, provenance). Fraunces (display serif) + Work Sans (body) +
IBM Plex Mono (accession numbers, prices, tags) carry that through typographically, and each card
has a folded specimen-tag corner as the one recurring signature detail.
